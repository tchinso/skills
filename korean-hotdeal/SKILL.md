# 국내 핫딜 찾기

사용자가 사고 싶은 상품의 **지금 구매 가능한 특가**를 원본 게시글과 판매 페이지에서 확인한다. 기본 답변 언어는 한국어다.

## 검색 범위

- [references/sources.json](references/sources.json)이 검색 대상의 유일한 목록이다. 14개 커뮤니티 도메인의 27개 게시판·채널이며, 같은 도메인의 게시판도 각각 확인한다.
- 사용자가 범위를 줄이지 않았다면 매 요청에서 27개 모두 검색을 시도한다. 관련성이 높은 곳부터 시작하되 패션·육아 등 관련성이 낮은 곳도 임의로 생략하지 않는다. 구매 가능한 후보의 판매처 확인을 위해서는 목록 밖의 판매 사이트를 열 수 있다.
- 항상 실행 시점에 웹을 조회한다. 저장된 상품 가격, 과거 실행, 검색 요약만으로 현재 특가를 만들지 않는다. 웹 도구가 없으면 실시간 조회를 할 수 없다고 명시한다.
- 목록은 2026-10-24 확인한 원본 주소다. 주소가 바뀌면 해당 커뮤니티의 공식 메뉴에서 같은 게시판을 찾는다. 확인할 수 없으면 그 출처를 확인 불가로 남긴다.

## 요청 해석

예산·용도·모델·신품/중고·직구 허용 여부 등 사용자가 준 조건을 따른다. 조건이 부족해도 먼저 검색할 수 있으면 진행한다. 추천에 꼭 필요한 사항만 짧게 질문하고 독립적인 검색은 계속한다.

“컴퓨터 사고 싶어”는 완제품 데스크톱·미니PC·노트북을 우선 찾아 종류별로 구분한다. `컴퓨터, PC, 데스크탑, 완본체, 미니PC, 노트북`처럼 동의어를 확장한다. 모니터나 개별 부품을 완제품 대신 추천하지 않는다. 예산·용도가 미정이면 그 가정을 밝히고 후보를 보여준다. 다른 상품도 통상 명칭·영문명·모델 변형을 함께 검색하되 사용자가 원하지 않은 품목으로 넓히지 않는다.

## 27개 출처 검색

1. 출처 목록을 읽고 출처별 검색 기록을 만든다. 필요하면 아래 도우미로 검색 쿼리와 빈 확인 기록을 생성한다. 도우미는 계획만 만들며 웹 검색·재고 확인을 실행하지 않는다.

   ```bash
   python scripts/plan_search.py 컴퓨터 PC 데스크탑 완본체 미니PC 노트북 --output search-plan.json
   ```

   경로는 이 스킬 폴더 기준이다. 도우미 없이 같은 목록을 직접 처리해도 된다. `query_batches`는 웹 검색에 바로 전달할 수 있는 `q`·`recency` 쿼리를 호출당 최대 4개씩 묶는다. `coverage`에 출처별 쿼리와 기록이 있으며 초기 `not_searched`는 아직 조회하지 않았다는 뜻이다.

2. 최근 72시간 게시물을 먼저 찾고, 후보가 부족하면 최근 7~14일까지 넓힌다. 오래된 글도 실제 판매 페이지에서 현재 조건이 유지되는 경우에만 후보로 쓸 수 있다. 검색 엔진의 수집일·기간 필터를 게시일이나 재고 증거로 쓰지 않는다.
3. 각 게시판의 최신 목록·검색 기능과 출처 제한 웹 검색을 활용한다. **사용자의 브라우저와 기존 세션을 적극 활용**해 동적 목록·내부 검색·게시글·판매처를 직접 읽는다. 웹 검색에 안 나오거나 웹 조회 도구에서 막혔다는 이유만으로 멈추지 않는다. 수집 전에 [references/browser-collection.md](references/browser-collection.md)를 읽고 도구별 실패에 맞는 직접 HTTP 조회·브라우저·DOM 수집으로 이어간다. 디시인사이드는 gallery id와 말머리가 모두 일치하는지 확인한다.
4. 독립적인 출처 묶음을 병렬로 검색할 수 있다. 각 작업의 결과는 출처 ID, 실제 조회 방식, 후보 링크, 확인 시각, 접근 제한을 포함해야 한다. 같은 도메인의 다른 게시판이나 같은 상품의 중복 글을 별도 출처 확인으로 대체하지 않는다.
5. 각 출처의 상태와 실제 확인 기간·페이지·키워드, 일치 후보 수를 남기고 27개 항목을 대조한다. `원문 조사 완료`는 조사 기간의 최신 목록 또는 키워드 검색 범위를 원문으로 확인했을 때, `원문 일부 확인`은 목록 한 페이지만 봤거나 검색·페이지 이동을 끝내지 못했을 때 쓴다. 그 밖에는 `검색결과만 확인`, `접근 불가`, `미검색`으로 기록한다. 단순히 페이지가 열렸다는 이유로 조사 완료로 세지 않는다. 예산·도구 제한 등으로 남긴 범위도 공개하며 로그인·봇 차단·삭제로 못 본 결과를 추측하지 않는다.

출처 목록의 `search_scope`는 검색 후보를 좁히는 보조 표현이다. 검색 엔진이 URL 매개변수나 말머리를 정확히 구분한다고 가정하지 말고 원문 게시판을 확인한다. 본문이 실제로 보이는지 확인하며, HTTP 200인 차단 안내를 원문 열람 성공으로 세지 않는다. 가능한 조회 계층을 활용한 뒤에도 막히면 제한을 기록하고 다른 출처 검색을 계속한다.

## 후보 검증과 가격 비교

- 원본 게시글에서 모델·사양·구성·게시일·종료 표시를 읽고, 최신 수정과 댓글에서 품절·쿠폰 소진·가격 변경을 확인한다. 검색 결과 제목·가격만 확인한 후보는 현재 특가로 확정하지 않는다.
- 유망 후보는 판매 페이지도 열어 실제 옵션 가격·재고·배송비·필수 쿠폰·카드·멤버십·앱 조건을 확인한다. `구매 가능 확인`은 현재 판매 페이지에서 해당 옵션의 재고와 가격을 확인했을 때만 사용한다. 판매 페이지를 확인하지 못하면 `판매처 미확인`으로 분리해 표시한다. 로그인 후에만 알 수 있는 가격은 `로그인 조건 미확인`으로 남긴다.
- 종료·품절이 명확하면 추천에서 제외한다. 판매 페이지에 재입고나 가격 변경이 있으면 게시글의 과거 가격을 그대로 적용하지 않는다. 할인이나 재고를 검증하려고 결제·장바구니 변경을 진행하지 않는다.
- 누구나 가능한 즉시 구매가는 상품가 + 필수 배송비 - 확인된 즉시 할인으로 계산한다. 카드·회원·첫 구매·구독 등 조건부 가격을 별도로 표시한다. 적립금·추후 캐시백·보상판매액을 즉시 결제 금액에서 빼지 않는다. 확인되지 않은 비용은 0원으로 간주하지 않는다.
- 직구는 통화·환산 시점, 배송비, 확인 가능한 세금, 국내 보증 여부를 구분한다. 환산액·미확정 세금을 포함한 계산은 예상 금액임을 밝힌다.
- 같은 모델·옵션·판매처·행사는 하나로 묶고, 독립적인 원문 출처를 함께 연결한다. 용량·수량·배송·보증·신품/리퍼가 다르면 같은 가격처럼 비교하지 않는다.
- 추천 순서는 요청 적합성, 실제 구매 비용, 구매 가능성, 보증·판매처 신뢰도를 함께 본다. 추천 수·댓글 수만으로 특가를 판정하거나 검증 없이 “역대 최저가”를 쓰지 않는다. 비교 근거가 없으면 커뮤니티에 올라온 특가 후보라는 범위로 표현한다.

## 결과 전달

확인 시각을 `YYYY-MM-DD HH:mm KST`로 적고 가장 적합한 후보부터 보여준다. 보통 3~7개면 충분하지만 유효한 후보 수에 맞추며 개수를 채우려고 종료·미확인 딜을 넣지 않는다.

표에는 **상품·핵심 사양 / 즉시 구매가와 조건부 가격 / 판매처·구매 조건 / 확인 상태 / 원문·구매 링크**를 담는다. 각 가격·재고 주장을 뒷받침하는 직접 링크를 가까이 둔다. 확인된 결과가 없다면 그 사실과 제한을 말하고, 미확인 후보나 종료 딜은 필요할 때 별도 구분한다.

아래에 추천 이유와 주요 조건을 짧게 적는다. 마지막에는 `27개 중 원문 조사 완료 N · 일부 확인 N · 검색결과만 N · 접근 불가 N · 미검색 N`처럼 합계가 27인 검색 범위를 밝힌다. 조사 완료 외의 출처 이름과 남은 범위·제한을 나열한다. 사용자가 범위를 줄였으면 분모를 실제 대상으로 바꾸고 그 범위를 명시한다. “전체 특가”, “최저가”처럼 실제 확인 범위보다 넓게 단정하지 않는다.
