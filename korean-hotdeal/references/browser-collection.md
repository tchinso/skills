# 원문을 최대한 수집하는 방법

검색 엔진은 발견 도구이며 27개 게시판 전체를 대신하지 않는다. 같은 URL도 웹 조회 도구에서는 실패하고 일반 HTTP 요청이나 사용자의 브라우저에서는 정상적으로 보일 수 있다. 수집은 읽기 작업이다.

## 조회 수단 선택

- 검색 도구로 후보를 찾고 원본 게시판과 판매처를 직접 연다. 최신 목록이 잘 보이고 충분한 후보가 검증되었다면 같은 조회를 여러 도구에서 반복하지 않는다.
- HTML 조회가 제한되거나 비어 있으면 일반 공개 HTTP 요청 또는 브라우저로 확인한다. 직접 HTTP 요청은 로그인 없이 공개된 주소에 한정하고 응답 문자 인코딩을 따른다. 사용자의 쿠키·토큰·브라우저 프로필을 터미널이나 별도 HTTP 클라이언트로 추출하지 않는다.
- **사용자의 실제 브라우저를 우선 활용한다.** 사용자가 브라우저를 지정했으면 그대로 따르고, 아니면 사용 가능한 브라우저 목록에서 해당 사이트를 열 수 있는 사용자 브라우저를 고른다. 기존 세션을 사용하되 열려 있는 사용자 탭을 덮어쓰기보다 같은 브라우저의 작업용 새 탭을 사용한다. 연결된 사용자 브라우저가 없으면 사용 가능한 인앱 브라우저로 진행한다.
- 브라우저 도구의 초기화·문서·허용 API를 먼저 따른다. DOM·접근성 트리가 충분하면 이를 사용하고, 필요한 내용이 화면에만 있으면 스크린샷과 UI를 활용한다. 도구에 없는 비공개 API나 앱 내부 상태에 의존하지 않는다.
- 브라우저 작업은 가능한 한 백그라운드로 진행한다. 사용자가 보고 있는 탭·포커스를 불필요하게 바꾸지 않고 관련 없는 탭·방문 기록은 읽지 않는다. 작업용 탭은 결과 전달 후 정리하되 사용자가 열어 둔 탭은 닫지 않는다.

## 게시판·검색·상세 수집

1. 실제 게시판 제목과 게시글 목록이 있는지 확인한다. 로그인·봇 확인·IP 차단 안내는 내용 열람 성공이 아니다. 브라우저가 정상적인 자동 리다이렉트를 마치도록 기다릴 수는 있지만 검증을 위조하거나 접근 제한을 우회하지 않는다.
2. 원본 게시판의 검색 UI에 상품명·동의어를 입력한다. 검색어 OR 문법이 지원되지 않으면 짧은 키워드로 나누고, URL 매개변수·문자 인코딩을 추측해 조립하지 않는다. 디시인사이드는 지정 gallery id와 핫딜/할인/특가 말머리를 유지한다.
3. 동적 목록은 더보기·다음 페이지·스크롤을 실제 UI로 진행하며 제목·링크·게시일·가격·종료 표시를 DOM 또는 접근성 트리에서 모은다. 핀 고정 글의 날짜만으로 중단하지 않는다. 일반 글이 조사 기간 이전으로 넘어가고 현재 검색 결과를 충분히 확인했으면 멈춘다. 새 결과가 없는 페이지를 반복하지 않는다. 커뮤니티 검색 순서가 날짜순인지도 확인한다.
4. 상품 조건에 맞는 게시글을 열어 본문과 최신 댓글·수정 내용을 확인하고 구매 링크를 따라 판매처의 해당 옵션을 검증한다. 판매 페이지도 JS 렌더링·앱 유도 등으로 읽히지 않으면 사용자의 브라우저에서 확인한다. 같은 상품을 여러 커뮤니티에서 찾았다면 검증된 판매 페이지를 재사용하되 조건이 다르면 다시 비교한다.
5. 수집한 행마다 출처 ID·원문 URL·상품·옵션·표시 가격·조건·게시 시각·확인 시각·상태를 유지한다. 출처별로 실제 확인한 기간·페이지·검색어와 조사 완료 여부도 기록한다. 내부 검색 로그인 요구 등으로 최신 목록 일부만 본 경우 `원문 일부 확인`으로 보고한다. 페이지가 바뀌거나 더보기를 눌렀으면 최신 UI 상태를 다시 읽어 오래된 요소 번호를 재사용하지 않는다.

뽐뿌는 EUC-KR이므로 한글 검색에 브라우저 UI가 유용하다. 딜바다·빠삭의 짧은 검색어 제한은 실제 안내에 맞춰 조정한다. 몰테일의 검색이 통합 검색이면 결과가 지정 핫딜 게시판에 속하는지 확인한다.

## 멈춤과 보고

- 로그인된 세션으로 공개적으로 볼 수 있는 목록·상세는 읽을 수 있다. 새 로그인이나 CAPTCHA 등 사용자 조작이 필요한 단계는 사용하는 도구의 확인 규칙을 따르고, 나머지 출처를 먼저 진행한다. 인증을 우회하거나 차단을 피해 프록시·계정·IP를 바꾸지 않는다.
- 429·명시적 IP 차단에는 반복 요청을 보내지 않는다. 일시적 로딩 실패는 새 상태 확인이나 정상 재열람으로 복구하되, 같은 실패가 반복되면 중단한다.
- 원문 접근 방식이 하나 실패했을 때 다른 정상 조회 수단을 활용하는 것과 접근 통제를 우회하는 것을 구분한다. 어느 방식도 정상적인 본문을 보여 주지 않으면 `접근 불가`, 검색 엔진의 결과만 보였으면 `검색결과만 확인`이다.
- 브라우저를 사용할 수 없거나 본문을 읽지 못한 사실을 숨기지 않는다. 검색 요약으로 원문 내용·재고를 추정하거나 자동 수집이 완료됐다고 주장하지 않는다.
